# Publish to Widgetbook Cloud

Self-hosting means running `flutter build web` and serving the output yourself. [Widgetbook Cloud](/cloud) hosts it instead: one build per commit, plus visual reviews on every pull request.

Widgetbook itself stays [open source](https://github.com/widgetbook/widgetbook) and free. Cloud is optional.

| | Self-hosted | Widgetbook Cloud |
| --- | --- | --- |
| Browse the catalog | Build and host it yourself | Hosted build per commit |
| Share a story | Deep link plus [`preview`](/sharing/embedding) | Same, on a stable URL |
| Visual regressions | Write and maintain goldens yourself | Every scenario diffed per PR |
| Review UI changes | Not available | [Reviews](/cloud/reviews) with comments and sign-off |

Cloud snapshots come from the [Scenarios](/testing/overview) you already wrote, so there are no separate visual tests to maintain. See [What are Visual Tests?](/testing/visual-tests).

## Push a Build

<Steps>
  <Step title="Generate snapshots">
    Writes snapshot images and metadata to `build/.widgetbook`. See [Run Scenarios](/testing/run-scenarios).

    ```bash
    dart run build_runner build -d
    flutter test
    ```
  </Step>

  <Step title="Build for the web">
    ```bash
    flutter build web
    ```
  </Step>

  <Step title="Push">
    ```bash
    dart pub global activate widgetbook_cli {{ versions.cli }}
    widgetbook cloud build push --api-key PROJECT_API_KEY
    ```
  </Step>
</Steps>

`cloud build push` uploads `build/.widgetbook/` for the review workflow and `build/web/` for the browsable build.

<Info>
  Run this manually once to see the pieces, then move it to CI so every commit gets a build. [Upload builds](/cloud/builds/upload) has guides for GitHub, GitLab, Azure DevOps, Bitbucket, and Codemagic.
</Info>
