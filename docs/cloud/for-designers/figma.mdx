# Compare against Figma

Today the comparison runs between Widgetbook Cloud and Figma, side by side.

## How it works today

The developer sets a design link on a story, a link to the matching component in the Figma file.
In the review the link shows as a **View in Figma** button.
Click through to compare the implementation against the design by eye.

<Image src="/assets/cloud/reviews/view-in-figma.png" zoom caption="Click View in Figma on the story" />
<Image src="/assets/cloud/reviews/figma-design.png" zoom caption="The matching component opens in the Figma file" />

The developer setup lives in [Figma Reviews](/cloud/reviews/figma).
Because the link points at a specific Figma component, a few habits in Figma make the comparison faster and more accurate:

- **Keep component naming stable.** The link targets a component by its Figma URL. Renaming, restructuring, or replacing components breaks the link and points the review at the wrong place. Stable names and structure keep links pointing where they should.
- **Design the states that will be built.** A developer can only link to a state that exists in Figma. Design empty, loading, error, and edge states explicitly, and the review compares against them instead of a guess.
- **Specify tokens, not raw values.** A design that names a token (a colour, a spacing step, a type style) rather than a literal value gets implemented as that token and stays consistent as the system changes. Raw values in the design invite raw values in the code, and those drift.
