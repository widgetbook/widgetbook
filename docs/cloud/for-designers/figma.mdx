# Working with Figma

A review is only as good as what you compare against. Today that comparison runs between Widgetbook Cloud and Figma, side by side.

## How it works today

The developer sets a design link on a story, a link to the matching component in your Figma file. In the review it shows as a **View in Figma** button. You click through and compare the implementation against the design by eye.

<Image src="/assets/cloud/figma-review.png" zoom />

The developer setup lives in [Figma Reviews](/cloud/reviews/figma). Because the link points at a specific Figma component, a few things you control in Figma make the comparison faster and more accurate:

- **Keep component naming stable.** The link targets a component by its Figma URL. Renaming, restructuring, or replacing components breaks the link and points the review at the wrong place. Stable names and structure keep links pointing where they should.
- **Design the states that will be built.** A developer can only link to a state that exists in Figma. Design empty, loading, error, and edge states explicitly, and the review compares against them instead of a guess.
- **Specify tokens, not raw values.** When your design names a token (a colour, a spacing step, a type style) rather than a literal value, the developer implements the token and the result stays consistent as the system changes. Raw values in the design invite raw values in the code, and those drift.
