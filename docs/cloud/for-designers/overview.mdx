# For Designers

Widgetbook Cloud has two audiences: the developers who build the UI, and the designers who own how it should look. Most of these docs are written for developers. This section is for you. It assumes you have never opened a Flutter project and never will.

You do not need to run code, check out a branch, or install anything. Every pull request produces a [review](/cloud/reviews) you open in your browser. You compare the implementation against your design and leave feedback the developer sees on the change itself.

## The two-stage review

A single UI review has two passes. They are usually done by two different people.

1. **Filter out the unintended.** The developer who opened the pull request looks first, for changes they did not mean to make. A component that shifted, spacing that moved, a state that now renders differently. They fix those before asking anyone else to look.
2. **Judge whether it is right.** Once only intentional changes remain, the next reviewer decides whether those changes are correct. When that is a design question, that reviewer is you.

The first pass is a filter. A review that reaches you should contain only deliberate changes. Your job is not to hunt for accidents the developer already caught. It is to judge whether the deliberate changes are right.
