# For Designers

Widgetbook Cloud has two audiences: the developers who build the UI, and the designers who own how it should look.
Most of these docs are written for developers.
This section is for designers, who usually never open Flutter projects and likely never will.

Reviewing a UI change needs no code, no branch checkout, and no local setup.
Every pull request produces a [review](/cloud/reviews) that opens in the browser.
Open the review, compare the implementation against the design, and leave feedback the developer sees on the change itself.

## The two-stage review

A single UI review has two passes.
Two different people usually run them.

1. **Filter out the unintended.** The developer who opened the pull request looks for changes they did not mean to make. A component that shifted, spacing that moved, a state that now renders differently. They fix those before asking other team members to review.
2. **Judge whether the change is right.** Once only intentional changes remain, the next reviewer decides whether those changes are correct. When the question is a design one, that reviewer is a designer.

The first pass is a filter.
A review that reaches a designer should contain only deliberate changes.
A designer does not re-hunt for accidents the developer already caught.
A designer judges whether the deliberate changes are right.
