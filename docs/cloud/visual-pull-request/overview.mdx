# Visual Pull Requests

A visual pull request mirrors a pull request in your Git provider.
Where the code pull request diffs source between the `base` and `head` commits, the visual pull request diffs the [builds](/cloud/builds/overview) of those commits.

<Image src="/assets/cloud/visual-pull-request/example.png" caption="Widgetbook Cloud visual pull request" zoom />

|                | Code pull request                       | Visual pull request                                                              |
| -------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| **Purpose**    | Bugs, performance, code quality         | UI differences against the design, and regressions between versions              |
| **Compares**   | Code between `base` and `head` commits  | Snapshots and semantics trees between `base` and `head` [builds](/cloud/builds/overview) |
| **Tool**       | GitHub, GitLab, Azure DevOps, Bitbucket | Widgetbook Cloud                                                                 |

Both stay in sync: the visual pull request is created automatically when the code pull request is opened, and its [review](/cloud/reviews) decision is reported back as a commit status.

## What Lands in the Change Set

A scenario appears in the visual pull request when any of the following differ between the two builds:

- The [snapshot](/cloud/visual-tests/overview) pixels.
- The [semantics tree](/cloud/accessibility/regressions).
- The [accessibility violations](/cloud/accessibility/violations) it introduces or resolves.
