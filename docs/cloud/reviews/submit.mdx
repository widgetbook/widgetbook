# Submit a Review

The diff view shows the `base` version on the left and the `head` version on the right, one entry per changed scenario.

<Image src="/assets/cloud/visual-pull-request/example.png" zoom />

## Show Diff

Shades the changed pixels in pink, so a small shift is visible without hunting for it.
The control sits in the top-right of a story diff, on the `d` shortcut.

<Image src="/assets/cloud/reviews/show-diff.png" zoom caption="Show diff shades the changed pixels in pink" />

## Mark as Viewed

Tracks how far you got through the changed scenarios.
The counter in the header shows the progress.
A scenario resets to unviewed when a later build changes it again.
The control sits next to **Show diff**, on the `v` shortcut.

## Comment

Ties feedback to one scenario, so it names the exact component and state to fix.
Use the comment section below the story diff.
Click **Single comment** to post it on its own, or **Start a review** to collect several comments and publish them together.

<Image src="/assets/cloud/reviews/add-comment.png" zoom caption="Comment on a story diff" />

## Publish a Decision

Click **Review changes** in the top-right corner, pick a status, and click **Submit Review**.
The button reads **Finish your review** instead once you started a review from a comment.

<Image src="/assets/cloud/reviews/submit-review.png" zoom />

| Status | Commit status | Merge |
| --- | --- | --- |
| **Approved** | Successful | Allowed |
| **Comment** | Pending, unless another status overrides it | Unchanged |
| **Changes requested** | Failed | Blocked until revised |

<Info>
  With [required reviewers](/cloud/reviews/required-reviewer) configured, at least one required reviewer must approve before the visual pull request counts as approved.
  Where the review check is [enforced](/cloud/guides/github/enforce-reviews), a missing approval blocks the merge on its own, so a comment leaves the pull request blocked.
</Info>
