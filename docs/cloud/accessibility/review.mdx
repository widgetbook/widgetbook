# Reviewing Changes

When a pull request changes the accessibility tree of a scenario, Widgetbook Cloud shows an **Accessibility Changes** section on that scenario's story diff, right next to the visual diff. It appears whenever the semantics tree differs, **even if the screenshot is identical**.

<Image src="/assets/cloud/accessibility/story-diff-accessibility.png" caption="Accessibility Changes and Accessibility Violations on a story diff" zoom />

## Reading a Change

Each entry represents a node in the semantics tree that changed between the `base` and `head` builds. The header shows the node's path in the tree, a color-coded icon, and the **type** of change:

| Icon | Type        | Meaning                                                                                          |
| ---- | ----------- | ------------------------------------------------------------------------------------------------ |
| 🟩   | **Added**   | A node exists in the new version but not the old one. An element was added to the tree.           |
| 🟥   | **Removed** | A node existed in the old version but not the new one. An element was dropped from the tree.      |
| 🟨   | **Changed** | A node's properties differ, for example its `label` or `value`.                                   |
| ↩️   | **Moved**   | A node's position among its siblings changed, altering the order assistive technologies read it.  |

Expanding a **changed** entry shows a table comparing the node's properties:

| Property | Previous       | Current        |
| -------- | -------------- | -------------- |
| label    | `Basket: 0$`   | `Basket: 1$`   |

Compared properties include `label`, `value`, `hint`, `tooltip`, `role`, `headingLevel`, `textDirection`, flags (such as `isButton`, `isHeader`, `isSelected`), and geometry (`rect`, `transform`).

<Info>
**Role changes appear as a removed + added pair.** A node's `role` is part of how Widgetbook matches nodes between versions, so changing a role (for example, from a button to plain text) is reported as the old node being **removed** and a new node being **added**, rather than a single change.
</Info>

## Accessibility Violations

Below the changes, the story diff lists the [accessibility guideline](/cloud/accessibility/guidelines) violations found in the latest build, with **new violations** called out so you catch them in the pull request. Each violation shows:

- a **severity** level, such as `SERIOUS`,
- the guideline that failed, such as `Tap target too small` or `Tappable without a label`,
- a **message** with the specifics, such as `Expected at least 48×48, found 358×24`, and
- a **docs** link to the relevant accessibility guideline.

Configure which guidelines run from your Widgetbook app. See [Accessibility guidelines](/cloud/accessibility/guidelines).

## Reviewing Alongside Visual Changes

Accessibility changes are part of the same [review](/cloud/reviews) as visual changes. On each story diff you can:

- **Accept** or **reject** the change to record whether it was intentional.
- **Comment** to discuss it with your team.
- **Mark as viewed** to track review progress.

A story appears in the pull request's change set when its screenshot changed **or** its accessibility tree changed, so an accessibility-only regression still surfaces for review even when nothing looks different.

<Info>
For the end-to-end review workflow (commit statuses, required reviewers, and notifications), see [Widgetbook Cloud Reviews](/cloud/reviews).
</Info>
